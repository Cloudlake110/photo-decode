# Core Model — Analysis Before Style

Photo Decode V2 is a **visual reasoning system**, not a visual preset.

## What the system solves

Given a complex image, identify the smallest set of structures and relationships that make it visually itself, then reconstruct those structures as a new flat composition.

The system optimizes for four simultaneous goals:

1. **Recognition** — the source remains traceable.
2. **Compression** — incidental detail and photographic background disappear.
3. **Reconstruction** — the result is newly designed rather than filtered.
4. **Explanation** — palette and key elements reveal why the reconstruction works.

## Visual Structure Ledger

Before generation, reason through:

| Field | Question |
|---|---|
| Anchor | What does the eye lock onto first? |
| Hierarchy | What is hero, support, tertiary? |
| Spatial grammar | What relationships define the composition? |
| Identity cues | Which shapes/details cannot disappear? |
| Action/tension | What forces, gestures or directional flows matter? |
| Rhythm | What repeats or creates cadence? |
| Keep | What survives compression? |
| Delete | What can disappear without loss? |
| Source-style cues | Which visual traits belong to this specific image? |
| Key grammar candidates | Which 4–6 units best explain the visual logic? |

## Compression is semantic, not cosmetic

Do not reduce detail just because “flat” sounds minimal.

Examples:

- An ornate temple may remain highly detailed because ornament hierarchy is identity-defining.
- A portrait may become much simpler because silhouette, gaze, hair and garment structure carry recognition.
- A city scene may retain dense stacked rooflines but delete photographic glow and unrelated buildings.
- A sports collision may retain intersecting bodies/vehicles and impact geometry while dropping stadium background.

The target complexity is determined by **meaning**, not by a universal minimalist aesthetic.
